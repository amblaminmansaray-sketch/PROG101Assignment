1. Problem Description
The selected community problem is the difficulty of coordinating waste collection in communities in Sierra Leone. Waste may accumulate around homes, markets, streets and drainage areas when collection requests are not recorded consistently, vehicles are unavailable, or the status of a collection is not tracked. This project proposes a logical Community Waste Management System that records collection requests, checks vehicle availability, assigns available vehicles and tracks whether a request is completed or remains pending.
The purpose of the project is to design how a system should work. It is not a requirement to write a working computer program. The solution is expressed through an algorithm, pseudocode, a flowchart, functional modules and sample outputs.
2. Background and Problem Analysis
2.1 The community problem
The central problem is that waste collection can be difficult to organize when there is no simple, consistent way to register requests and follow them through to completion. If information about a location or the collection status is missing, local coordinators may not know which areas need attention first. A request may also be delayed when no collection vehicle is available.
2.2 Who is affected?
Residents, market traders, community leaders, waste collectors and local authorities may all be affected. Residents and traders need cleaner surroundings; collection teams need clear information about where to go; and local authorities need a way to see which requests have been completed and which still require action.
2.3 Why the problem exists
Possible causes include incomplete reporting, poor coordination between communities and collection teams, limited vehicle availability, and a lack of consistent status updates. These are the conditions the proposed logical solution is designed to address; the report does not claim that one system alone can resolve every waste management challenge.
2.4 Why a logical solution is needed
A consistent process can ensure that each request is recorded, checked and given a clear status. When a vehicle is available, the request can be scheduled. When no vehicle is available, the request can remain on a pending list rather than being lost. After collection, the status can be updated so the coordinator can distinguish completed work from outstanding work.
3. Proposed Solution
The proposed Community Waste Management System is a simple request-management process for a community coordinator. The coordinator enters a location, waste type and estimated quantity. The system checks that the required details have been provided and registers the request. It then checks vehicle availability. If a vehicle is available, it is assigned and collection is scheduled. If no vehicle is available, the request is marked pending. For scheduled requests, the collection status is checked and updated. The system displays the result and can repeat the process for another request.
The initial design is intentionally limited to the core process. In a later version, the system could include priorities for urgent locations, a vehicle register, dates and times, notifications, and reports. Those additions would need their own requirements and logic.
